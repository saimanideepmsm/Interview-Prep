# Kubernetes – Basic `kubectl` Pod Commands

This README covers the basic `kubectl` commands used to create, inspect, access, troubleshoot, expose, view logs, and delete Kubernetes Pods.

---

## 1. Basic `kubectl` Pod Commands

`kubectl` is the command-line tool used to communicate with a Kubernetes cluster.

Basic structure:

```bash
kubectl <command> <resource> <name>
```

For example:

```bash
kubectl get pods
```

Here:

* `kubectl` → Kubernetes command-line tool
* `get` → action
* `pods` → Kubernetes resource

---

# 2. Apply a YAML File

The `apply -f` command creates or updates Kubernetes resources using a YAML manifest.

```bash
kubectl apply -f <filepath>
```

Example:

```bash
kubectl apply -f nginx-pod.yaml
```

You can also specify a complete path:

```bash
kubectl apply -f .\nginx-pod.yaml
```

### What does `-f` mean?

`-f` means **filename**.

It tells Kubernetes to read the resource definition from the specified file.

Example YAML:

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: nginx-pod

spec:
  containers:
    - name: nginx
      image: nginx
```

Apply it:

```bash
kubectl apply -f nginx-pod.yaml
```

# 3. Get Pods

To list Pods in the current namespace:

```bash
kubectl get pods
```

Example:

```text
NAME         READY   STATUS    RESTARTS   AGE
nginx-pod    1/1     Running   0          2m
```

### Get Pods with additional information

```bash
kubectl get pods -o wide
```

This provides additional information such as:

* Pod IP
* Node where the Pod is running
* Container status

Example:

```text
NAME        READY   STATUS    IP           NODE
nginx-pod   1/1     Running   10.244.0.5   local-cluster
```

---

# 4. Get Details of a Specific Pod

You can retrieve a specific Pod using its name:

```bash
kubectl get pod <podname>
```

Example:

```bash
kubectl get pod nginx-pod
```

---

# 5. Get Pod Output in Different Formats

Kubernetes allows you to view the complete Pod definition in different formats.

## Wide Output

```bash
kubectl get pod <podname> -o wide
```

Example:

```bash
kubectl get pod nginx-pod -o wide
```

Useful for quickly checking:

* Pod IP
* Node
* Status
* Readiness

---

## JSON Output

```bash
kubectl get pod <podname> -o json
```

Example:

```bash
kubectl get pod nginx-pod -o json
```

JSON is useful when working with:

* Scripts
* Automation
* APIs
* Programmatic processing

---

## YAML Output

```bash
kubectl get pod <podname> -o yaml
```

Example:

```bash
kubectl get pod nginx-pod -o yaml
```

This displays the Pod definition and its current state.

YAML output is particularly useful when troubleshooting or understanding how Kubernetes represents a resource.

# 6. Describe a Pod

The `describe` command provides detailed, human-readable information about a Pod.

```bash
kubectl describe pod <podname>
```

Example:

```bash
kubectl describe pod nginx-pod
```

It provides information such as:

* Pod name
* Namespace
* Node
* IP address
* Containers
* Images
* Ports
* Volumes
* Conditions
* Events
* Restart information

### Events

One of the most useful sections is:

```text
Events:
```

It can help identify problems such as:

* Image pulling failures
* Container crashes
* Scheduling problems
* Volume mounting errors
* Permission issues

When troubleshooting a Pod, `describe` is often one of the first commands to use.

# 7. Get Inside a Pod

You can execute a command inside a running container using:

```bash
kubectl exec -it <podname> -- bash
```

Example:

```bash
kubectl exec -it nginx-pod -- bash
```

### Meaning

```text
kubectl exec
    │
    ├── -i → Keep standard input open
    ├── -t → Allocate a terminal
    ├── nginx-pod → Pod name
    ├── -- → Separates kubectl arguments from the command
    └── bash → Command to execute
```

After running it, you can interact with the container's shell.

For example:

```bash
ls
```

```bash
pwd
```

```bash
cd /usr/share/nginx/html
```

To exit:

```bash
exit
```

---

# 8. Get Inside a Specific Container

A Pod can contain multiple containers.

If the Pod contains multiple containers, specify which container you want to enter:

```bash
kubectl exec -it <podname> -c <containername> -- bash
```

Example:

```bash
kubectl exec -it my-pod -c nginx-container -- bash
```

Here:

* `my-pod` → Pod name
* `-c` → specifies the container
* `nginx-container` → container name
* `bash` → shell to execute

### Why is `-c` needed?

Imagine:

```text
Pod
│
├── nginx-container
│
└── sidecar-container
```

Kubernetes needs to know which container you want to access.

Therefore:

```bash
kubectl exec -it my-pod -c nginx-container -- bash
```

# 9. Port Forwarding

Port forwarding allows you to access an application running inside a Pod from your local machine.

Command:

```bash
kubectl port-forward <podname> <local-port>:<pod-port>
```

Example:

```bash
kubectl port-forward nginx-pod1 8080:80
```

This means:

```text
Your Computer
localhost:8080
      │
      │ port-forward
      ▼
Kubernetes Pod
port: 80
      │
      ▼
    Nginx
```

You can then access Nginx from your browser:

```text
http://localhost:8080
```

### Important

Port forwarding is mainly useful for:

* Local development
* Testing
* Debugging
* Temporarily accessing a Pod

It is **not normally how you expose a production application**. Kubernetes Services are generally used for that purpose.

# 10. View Pod Logs

To view logs from a Pod:

```bash
kubectl logs <podname>
```

Example:

```bash
kubectl logs nginx-pod
```

This is useful for troubleshooting application behavior.

For example:

```text
10.244.0.1 - - [11/Sep/2026:10:15:21 +0000] "GET / HTTP/1.1" 200
```

---

## Logs from a Specific Container

If the Pod contains multiple containers:

```bash
kubectl logs <podname> -c <containername>
```

Example:

```bash
kubectl logs my-pod -c nginx-container
```

---

## Follow Logs in Real Time

You can continuously watch logs using:

```bash
kubectl logs -f <podname>
```

`-f` means **follow**.

Example:

```bash
kubectl logs -f nginx-pod
```

Press:

```text
Ctrl + C
```

to stop following the logs.

---

# 11. Delete Resources Using a YAML File

You can delete the resources defined in a YAML file using:

```bash
kubectl delete -f <filename>
```

Example:

```bash
kubectl delete -f nginx-pod.yaml
```

If `nginx-pod.yaml` created an Nginx Pod, Kubernetes will delete that Pod.

You can verify:

```bash
kubectl get pods
```

---

# 12. `apply` vs `delete`

These commands work with the same YAML file:

### Create / Update

```bash
kubectl apply -f nginx-pod.yaml
```

### Delete

```bash
kubectl delete -f nginx-pod.yaml
```

Think of it as:

```text
nginx-pod.yaml
      │
      ├── kubectl apply -f
      │       ↓
      │   Create / Update
      │
      └── kubectl delete -f
              ↓
           Delete
```

# 13. Quick Command Cheat Sheet

| Command                                         | Purpose                              |
| ----------------------------------------------- | ------------------------------------ |
| `kubectl apply -f <file>`                       | Create or update resources from YAML |
| `kubectl get pods`                              | List Pods                            |
| `kubectl get pod <pod>`                         | Get a specific Pod                   |
| `kubectl get pod <pod> -o wide`                 | Show additional Pod information      |
| `kubectl get pod <pod> -o json`                 | Display Pod as JSON                  |
| `kubectl get pod <pod> -o yaml`                 | Display Pod as YAML                  |
| `kubectl describe pod <pod>`                    | Detailed Pod information and events  |
| `kubectl exec -it <pod> -- bash`                | Open shell inside a Pod              |
| `kubectl exec -it <pod> -c <container> -- bash` | Open shell in a specific container   |
| `kubectl port-forward <pod> 8080:80`            | Forward local port to Pod port       |
| `kubectl logs <pod>`                            | View Pod logs                        |
| `kubectl logs -f <pod>`                         | Follow Pod logs                      |
| `kubectl logs <pod> -c <container>`             | View logs from a specific container  |
| `kubectl delete -f <file>`                      | Delete resources defined in YAML     |

# 14. Basic Troubleshooting Flow

When working with a Pod, a useful troubleshooting sequence is:

```bash
kubectl get pods
```

If the Pod is not running:

```bash
kubectl describe pod <podname>
```

Then check the logs:

```bash
kubectl logs <podname>
```

If you need to inspect the container:

```bash
kubectl exec -it <podname> -- bash
```

If you need to test the application from your laptop:

```bash
kubectl port-forward <podname> 8080:80
```

Then open:

```text
http://localhost:8080
```

# Key Takeaways

* `kubectl apply -f` → **Create or update** resources from YAML.
* `kubectl get pods` → **See Pods**.
* `kubectl get pod -o wide/json/yaml` → **View Pod information in different formats**.
* `kubectl describe pod` → **Detailed troubleshooting information**.
* `kubectl exec` → **Execute commands inside containers**.
* `-c` → **Select a specific container** in a multi-container Pod.
* `kubectl port-forward` → **Connect a local port to a Pod port**.
* `kubectl logs` → **View application/container logs**.
* `kubectl delete -f` → **Delete resources defined in a YAML file**.

A simple way to remember the workflow:

```text
CREATE
  │
  ▼
kubectl apply -f
  │
  ▼
CHECK
  │
  ├── kubectl get pods
  ├── kubectl describe pod
  └── kubectl get pod -o yaml
  │
  ▼
DEBUG
  │
  ├── kubectl logs
  └── kubectl exec
  │
  ▼
TEST
  │
  └── kubectl port-forward
  │
  ▼
DELETE
  │
  └── kubectl delete -f
```
