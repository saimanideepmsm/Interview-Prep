# Kubernetes Deployments – Quick Revision

This document contains quick revision notes for **Kubernetes Deployments**, including Deployments vs ReplicaSets, rolling updates, rollout history, annotations, and rollback.

---

## 1. What is a Deployment?

A **Deployment** is a Kubernetes resource used to manage and maintain a set of identical Pods.

It provides:

* Desired number of Pod replicas
* Rolling updates
* Rollbacks
* Version management
* Self-healing through ReplicaSets
* Declarative application updates

### Basic Architecture

```text
Deployment
    │
    ├── ReplicaSet
    │      ├── Pod
    │      ├── Pod
    │      ├── Pod
    │      └── Pod
    │
    └── ReplicaSet (previous version)
           └── Old Pods
```

**Important:**

> A Deployment manages ReplicaSets, and ReplicaSets manage Pods.

# 2. ReplicaSet vs Deployment

| Feature                      | ReplicaSet           | Deployment |
| ---------------------------- | -------------------- | ---------- |
| Maintains desired Pod count  | ✅                    | ✅          |
| Creates/Manages Pods         | ✅                    | ✅          |
| Rolling Updates              | ❌                    | ✅          |
| Rollback                     | ❌                    | ✅          |
| Revision History             | ❌                    | ✅          |
| Manages ReplicaSets          | ❌                    | ✅          |
| Recommended for applications | Usually not directly | ✅          |

### Simple way to remember

```text
ReplicaSet → "Keep N Pods running"

Deployment → "Manage application versions and Pods"
```

# 3. Advantages of Deployment over ReplicaSet

Deployments provide additional functionality on top of ReplicaSets.

### Main advantages

1. **Rolling Updates**

   * Update application versions without taking the application completely offline.

2. **Rollback**

   * Return to a previous application version if the new version has problems.

3. **Revision History**

   * Kubernetes maintains Deployment revisions.

4. **Version Management**

   * Makes application updates easier to manage.

5. **Automated ReplicaSet Management**

   * Deployment creates and manages ReplicaSets automatically.

### Remember

```text
Deployment
   ↓
Manages ReplicaSets
   ↓
Manages Pods
```

# 4. Rolling Update

By default, a Kubernetes Deployment uses the **RollingUpdate** strategy.

When you update the Deployment, Kubernetes gradually replaces the old Pods with new Pods.

Example:

```text
Before update:

ReplicaSet v1
├── Pod
├── Pod
├── Pod
└── Pod


During rolling update:

ReplicaSet v1          ReplicaSet v2
├── Pod                 ├── Pod
├── Pod                 ├── Pod
└── Pod                 └── Pod


After update:

ReplicaSet v2
├── Pod
├── Pod
├── Pod
└── Pod
```

This allows Kubernetes to update the application gradually instead of deleting all existing Pods at once.

# 5. Check Deployment Rollout History

To view the rollout history:

```bash
kubectl rollout history deployment/nginx-deployment-demo
```

Generic syntax:

```bash
kubectl rollout history deployment/<deployment-name>
```

Example output:

```text
deployment.apps/nginx-deployment-demo

REVISION  CHANGE-CAUSE
1         <none>
2         Initial deployment of nginx
```

### What is REVISION?

Each significant Deployment update creates a new **revision**.

Example:

```text
Revision 1 → Initial deployment
Revision 2 → Updated image
Revision 3 → Updated configuration
```

# 6. Annotations

Annotations allow us to attach additional metadata to Kubernetes resources.

Example:

```yaml
metadata:
  name: nginx-deployment-demo

  annotations:
    description: "This is a demo deployment for nginx"
    kubernetes.io/change-cause: "Initial deployment of nginx"
```

### Why are annotations useful?

They can be used to:

* Store additional information
* Document resources
* Record deployment changes
* Help with debugging and auditing
* Store metadata used by tools

---

# 7. `kubernetes.io/change-cause`

The annotation:

```yaml
kubernetes.io/change-cause
```

can be used to describe **why a Deployment revision was created**.

Example:

```yaml
annotations:
  kubernetes.io/change-cause: "Updated nginx image to version 1.27"
```

Then:

```bash
kubectl rollout history deployment/nginx-deployment-demo
```

may show:

```text
REVISION  CHANGE-CAUSE
1         Initial deployment of nginx
2         Updated nginx image to version 1.27
```

### Important

This makes Deployment history easier for humans to understand.

Instead of:

```text
REVISION  CHANGE-CAUSE
1         <none>
2         <none>
```

you can have:

```text
REVISION  CHANGE-CAUSE
1         Initial deployment
2         Updated nginx image
3         Increased replicas
```

# 8. Rollback

If a new Deployment version causes a problem, we can roll back to a previous revision.

### Roll back to the previous revision

```bash
kubectl rollout undo deployment/nginx-deployment-demo
```

Generic:

```bash
kubectl rollout undo deployment/<deployment-name>
```

---

## 9. Roll Back to a Specific Revision

Use:

```bash
kubectl rollout undo deployment/nginx-deployment-demo --to-revision=1
```

Generic syntax:

```bash
kubectl rollout undo deployment/<deployment-name> --to-revision=<revision-number>
```

### Example

Suppose:

```text
REVISION  CHANGE-CAUSE
1         Initial deployment
2         Updated nginx image
3         Updated configuration
```

To go back to revision 1:

```bash
kubectl rollout undo deployment/nginx-deployment-demo --to-revision=1
```

# 11. Quick Interview Revision

### Q: What is a Deployment?

A Deployment manages application Pods and provides features such as **rolling updates, rollbacks, and revision management**.

### Q: Does a Deployment create Pods directly?

Conceptually, a Deployment manages **ReplicaSets**, and ReplicaSets manage the Pods.

```text
Deployment → ReplicaSet → Pods
```

### Q: Why use Deployment instead of ReplicaSet?

Because Deployment provides:

* Rolling updates
* Rollbacks
* Revision history
* Version management
* Automated ReplicaSet management

### Q: What is the default Deployment strategy?

```text
RollingUpdate
```

### Q: How do you check Deployment history?

```bash
kubectl rollout history deployment/<deployment-name>
```

### Q: How do you roll back a Deployment?

```bash
kubectl rollout undo deployment/<deployment-name>
```

### Q: How do you roll back to a specific revision?

```bash
kubectl rollout undo deployment/<deployment-name> --to-revision=<revision>
```

### Q: What is `kubernetes.io/change-cause`?

An annotation used to record a human-readable explanation of why a Deployment revision/change was made.

## 13. Example Deployment

```yaml
apiVersion: apps/v1

kind: Deployment

metadata:
  name: nginx-deployment-demo

  annotations:
    description: "This is a demo deployment for nginx"
    kubernetes.io/change-cause: "Initial deployment of nginx"

spec:
  replicas: 4

  selector:
    matchLabels:
      app: nginx-demo

  template:
    metadata:
      labels:
        app: nginx-demo

    spec:
      containers:
        - name: nginx-container
          image: nginx:latest
          ports:
            - containerPort: 80
```
