# Kubernetes — Self-Healing & High Availability

## Topics Learned

### 1. Replica Management

Kubernetes can automatically manage multiple copies (replicas) of an application using the **ReplicaSet** feature.

### 2. ReplicaSet in Kubernetes

A **ReplicaSet** ensures that the desired number of Pod replicas are running.

In this example, the ReplicaSet is configured with **3 replicas** and selects Pods using the label `app: nginx-demo`. fileciteturn0file1L5-L14

### 3. Self-Healing

One of the key features demonstrated is Kubernetes **self-healing**.

- If a Pod is deleted, the ReplicaSet detects that the actual number of Pods is lower than the desired number.
- The ReplicaSet automatically creates a replacement Pod.
- If a node goes down, Kubernetes can recreate/reschedule the affected workload on a healthy node when another suitable node is available.

The practical exercise demonstrated Pod recreation after deleting a Pod and observed node-related Pod recreation. fileciteturn0file0L3-L3 fileciteturn0file0L12-L12

### 4. High Availability

Running multiple replicas helps keep an application available when individual Pods fail.

In the practical example, **3 Nginx Pods** were running simultaneously: fileciteturn0file0L5-L9

### 5. ReplicaSet Pod Naming

Pods created by the ReplicaSet follow the naming pattern:

```text
<ReplicaSet>-<HashValue>
```

Example:

```text
nginx-replicaset-demo-94nz9
```

The observed Pod names follow this pattern. fileciteturn0file0L5-L8

## Practical ReplicaSet Manifest

The manifest used creates an Nginx ReplicaSet with **3 replicas**. fileciteturn0file1L1-L20

```yaml
apiVersion: apps/v1
kind: ReplicaSet

metadata:
  name: nginx-replicaset-demo

spec:
  replicas: 3

  selector:
    matchLabels:
      app: nginx-demo

  template:
    metadata:
      name: ngnx-pod1
      labels:
        app: nginx-demo

    spec:
      containers:
        - name: nginx-container
          image: nginx:latest
          ports:
            - containerPort: 80
```
